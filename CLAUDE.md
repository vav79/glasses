# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Проект

Android-приложение (Kotlin, Jetpack Compose, интерфейс на английском и русском) для очков Ray-Ban Meta Gen 2 на базе Meta Wearables Device Access Toolkit (DAT SDK 1.0.1) и ИИ-провайдеров (Claude API; DeepSeek как альтернатива и запасной вариант). Package `ru.vasev.glasses`, minSdk 29, сборка только под `arm64-v8a`. Очков пока нет: снимки для «Что я вижу» можно брать с камеры телефона или из галереи, а в debug-сборке — из симулятора очков (MockDeviceKit).

Вкладки (порядок — по роли) и шестерёнка настроек справа от них:
- **Ассистент** — повседневный ИИ-агент: вопрос голосом или текстом → модель (по умолчанию `claude-sonnet-5-5`) → ответ голосом (на вопрос текстом — только на экране, «Озвучить» по кнопке); «Что я вижу» (глаз) — снимок и описание. Поиск в интернете (Claude), заметки «Запомни» со снимком и местом. Память разговора и кэш промпта.
- **Камера** — снимки и устройства: источники (снимки, микрофон, очки), видоискатель, затвор «Что я вижу», «Переведи» (весь текст на снимке, цены — по курсу ЦБ), «Запомни», лента последних снимков. Разговор общий с «Ассистентом».
- **Перевод** — живой перевод разговора с собеседником (9 языков), по умолчанию `claude-haiku-5-5`.
- **Навигация** — мои места (Отель, Дом, Машина, свои), цель «Куда?» (текст, голос, фото адреса), карточка цели и переход в навигатор (Яндекс / Google / Organic Maps).
- **Настройки** (шестерёнка, поверх вкладки, «Назад» закрывает) — ключи провайдеров, модель для каждой роли, запасная модель, моя валюта, навигатор; «Для разработчика» (журнал запросов, бывшая вкладка «Разработка»). Вкладок не больше четырёх.

## Команды

Окружение Windows. Gradle запускается на JBR из Android Studio, отдельного JDK нет:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat assembleDebug                 # сборка
.\gradlew.bat installDebug                  # сборка + установка на телефон по USB
.\gradlew.bat testDebugUnitTest             # unit-тесты (JVM, без устройства)
.\gradlew.bat testDebugUnitTest --tests "ru.vasev.glasses.translate.NoiseFilterTest"   # один класс
```

`adb` не в PATH: `$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe`. Тестовый телефон — Galaxy S25 Ultra. Если `adb devices` пуст, а Windows видит только «USB Composite Device» без «ADB Interface», на телефоне выключилась отладка по USB (Samsung сбрасывает её; ещё мешает «Автоблокировщик»).

Логи: `adb logcat -s LLM:D Translate:D Audio:D Glasses:D` (+ `Tools:D Rates:D Notes:D Location:D` для инструментов). `LLM` — строка на каждую попытку запроса к ИИ для сравнения моделей (`role= provider= model= status= latency= [first_text=] in= out= cache_read= cache_write= reasoning= web= photo=sent|placeholder|none fallback=no|yes(причина)`), `Translate` — задержки этапов перевода (`recognition=`, `translate=`, `tts_start=`, `end_of_speech→sound=`), `Audio` — маршрут звука, `Glasses` — ошибки ассистента и `Assistant: end_of_speech→sound=` (конец фразы → первый звук ответа).

### Debug-запуск сценариев без голоса

Только в debug-сборке (`MainActivity.handleDebugIntent`). Текст передавать через `adb shell "…"` с одинарными кавычками, иначе adb режет его по пробелу:

```powershell
adb shell "am start -n ru.vasev.glasses/.MainActivity --es question 'Что написано на вывеске?' --ez with_frame true"
adb shell "am start -n ru.vasev.glasses/.MainActivity --es language TURKISH --es translate_partner 'Merhaba'"
adb shell "am start -n ru.vasev.glasses/.MainActivity --es translate_me 'Добрый день'"
# модель для роли (сохраняется в настройках) и имитация сбоя Claude на следующий запрос:
adb shell "am start -n ru.vasev.glasses/.MainActivity --es model_assistant deepseek-v4-pro --es model_translation deepseek-flash"
adb shell "am start -n ru.vasev.glasses/.MainActivity --es style_gender female --es style_formality casual --es language SPANISH --es translate_me 'Я устала'"   # стиль общения
adb shell "am start -n ru.vasev.glasses/.MainActivity --es fail_claude server --es question 'Привет'"   # server|network|forbidden|ratelimit
# источник снимков (камера телефона запросит разрешение, если его нет):
adb shell "am start -n ru.vasev.glasses/.MainActivity --es image_source simulator"   # glasses|phone|simulator
adb shell "am start -n ru.vasev.glasses/.MainActivity --es tab camera"   # assistant|camera|translate|navigation|settings|development (журнал в настройках)
adb shell "am start -n ru.vasev.glasses/.MainActivity --es nav_to 'Ват Арун'"   # поиск цели, как в поле «Куда?»
adb shell "am start -n ru.vasev.glasses/.MainActivity --ez translate_view true"   # «Переведи, что вижу» кнопкой
# снимок из файла (проверка QR и ссылок): положить в files/ приложения, затем с question+with_frame или translate_view
# adb push qr.png /data/local/tmp/ ; adb shell "run-as ru.vasev.glasses cp /data/local/tmp/qr.png files/"
adb shell "am start -n ru.vasev.glasses/.MainActivity --es frame_file qr.png --ez translate_view true"
```

«Нет интернета» проверяется авиарежимом: `adb shell cmd connectivity airplane-mode enable|disable` (USB-отладка при этом работает). После проверок верните модели по умолчанию — debug-параметры их сохраняют.

Перед этим выдать разрешения: `adb shell pm grant ru.vasev.glasses android.permission.RECORD_AUDIO` (и `BLUETOOTH_CONNECT`).

## Секреты и конфигурация

**API-ключи провайдеров в сборку не входят.** Они вводятся на вкладке «Настройки» и хранятся на телефоне (`security/ApiKeyStore`, слот на `ProviderId`): AES-256-GCM одним ключом из Android Keystore (на S25 — StrongBox), в SharedPreferences `secure` лежит только `IV || шифротекст` на слот (`anthropic_key_ct`, `deepseek_key_ct`, …), в AAD — имя слота. Имена слота Anthropic и alias Keystore (`anthropic_api_key_v1`) остались от версии с одним ключом — не переименовывать, иначе сохранённый ключ перестанет расшифровываться. Расшифровка — в памяти: перед каждым запросом (провайдер подставляет ключ заголовком только в этот запрос: `x-api-key` у Anthropic, где клиент SDK собран с заглушкой, `Authorization: Bearer` у OpenAI-совместимых) и на экране «Настройки» ради последних 4 символов. Признак «ключ есть» — по наличию шифротекста, без расшифровки. EncryptedSharedPreferences не используем (устарела). Резервное копирование и перенос данных на другое устройство отключены (`allowBackup=false` + `res/xml/data_extraction_rules.xml`). Проверка, что ключа нет в APK: распаковать APK и искать `sk-ant` по всем файлам (в самом .apk строки сжаты). Ключи DeepSeek начинаются с `sk-`: в logcat искать шаблон `sk-[A-Za-z0-9_-]{16,}` — голое `sk-` даёт ложные совпадения (`task-display-area`). Не вводите ключ через `adb shell input text` — adbd пишет текст команды в logcat. Debug-запуск сценариев работает только после ввода ключа в приложении.

Остальное — в `local.properties` (в `.gitignore`), в код попадает через `BuildConfig` (`app/build.gradle.kts`):
- `mwdat_application_id`, `mwdat_client_token` — необязательны; в Developer Mode приложения Meta AI достаточно `0` (лог `Failed to read metadata … APPLICATION_ID` при этом ожидаем);
- `sdk.dir` писать с прямыми слешами (`C:/Users/...`) — экранированные обратные ломают AGP («Invalid file path»).

DAT SDK берётся из Maven Central, GitHub-токен не нужен.

## Архитектура

**`GlassesApp`** держит общие на всё приложение объекты: `GlassesManager`, `SpeechSource`, `AudioOutput` (+ `Speaker`). Обе вкладки пользуются одним распознавателем и одним TTS, чтобы не спорить за звук; при переключении вкладок `MainActivity.selectTab` останавливает другую.

**Звук — через сменные интерфейсы** (`speech/`), это точка будущего перехода на очки:
- `SpeechSource.listen(languageTag)` → `Heard(text, endOfSpeechAt)`. Реализация `PhoneMicSpeechSource` — системный `SpeechRecognizer`, **один экземпляр на всё время работы**: пересоздание на каждую фразу даёт `ERROR_SERVER_DISCONNECTED` (код 11), который обрывает непрерывный режим. `SpeechException.noSpeech` / `.transient` — тишина и временные сбои, их непрерывный режим проглатывает.
- `AudioOutput.speak(text, locale, channel)` возвращается после `onDone` TTS. Каналы `ME` («мне») и `PARTNER` (собеседнику).

**Bluetooth-гарнитура** (репетиция перед очками — они подключаются так же, по HFP + A2DP) — `AudioRouter`, `RoutedSpeechSource`, `PhoneSpeakerOutput`; логи под тегом `Audio`:
- `Talker.USER` (ассистент, «Я отвечаю») слушается микрофоном гарнитуры: `setCommunicationDevice(SCO)` + `MODE_IN_COMMUNICATION`, распознаватель Google при этом пишет с гарнитуры. `Talker.PARTNER` — всегда микрофон телефона.
- Канал `ME` — обычный медиа-маршрут (A2DP в гарнитуру). Канал `PARTNER` при подключённой гарнитуре — синтез в файл и `MediaPlayer.setPreferredDevice(встроенный динамик)` с `USAGE_MEDIA`: TTS не умеет выбирать устройство.
- **Ловушка:** после `clearCommunicationDevice()` SCO разрывается асинхронно (на Galaxy S25 + Buds Core ~1,5 с). Пока он жив, телефон «в звонке», и звук уходит в гарнитуру с громкостью звонка, хотя `routedDevice` рапортует динамик. Поэтому `releaseMic()` запускает ожидание (событие разрыва SCO + смена устройства связи, таймаут 3 с), а вывод перед воспроизведением вызывает `awaitRouteSettled()`; ожидание перекрывается временем перевода.
- Гарнитура отключилась или не включила микрофон за 4 с — молча работаем через телефон.

**ИИ-провайдеры** (`llm/`). `AssistantClient` (`claude/`) и `Translator` (`translate/`) задают только промпт, `max_tokens` (2048 / 300) и `Effort` (оба `NONE` — без размышлений), а всё остальное делает `LlmService`:
- Модель по роли — из `AiSettings` (по умолчанию Sonnet 5.5 / Haiku 5.5). Каталог — `ModelCatalog`: `claude-sonnet-5-5`, `claude-haiku-5-5`, `deepseek-flash` (DeepSeek-V4.1-Flash, видит фото), `deepseek-v4-pro` (только текст, картинка → 400). Старые `deepseek-v4-flash*` у DeepSeek выведены из работы.
- `ChatProvider` → `AnthropicProvider` (официальный Java SDK: effort `low`; `Effort.NONE` выключает размышления — у Sonnet 5.5 `thinking: {type: "between_tools"}` (`disabled` там даёт 400), у Haiku 5.5 `{type: "disabled"}`, оба только при effort не выше `high`; авто-кэш только для ассистента; server-side fallback `server-side-fallback-2026-07-01` только у Sonnet) и `OpenAiCompatibleProvider` (OkHttp + org.json, настраивается `ProviderConfig`: URL, слот ключа, `Dialect`). У DeepSeek thinking включён по умолчанию: `reasoning_effort` `none` и для перевода, и для ассистента; фото — data-URL с `detail: high` (при `low` картинка ужимается до 512×512 и мелкий текст не читается). OpenAI: `ProviderConfigs.OPENAI` и диалект готовы — добавить модели в каталог.
- Модели без фото получают снимки пометкой «[фото]». «Что я вижу» на модели без фото автоматически уходит в модель того же провайдера с фото (`ModelCatalog.visionFor`, метка «· для фото»).
- Запасная модель (`FallbackPolicy`, чистая логика под тестами): только если сбой у Claude — 403, 429, 5xx (в т. ч. 529) или обрыв связи — один повтор через DeepSeek Flash с таймаутом 20 с; не при 401/400 и не без ключа DeepSeek. Сети нет совсем (`ConnectivityManager`) — сразу «Нет интернета», ни одной попытки. Фото в запасную модель — только с разрешением в настройках (по умолчанию выключено): иначе «Что я вижу» отвечает «Claude недоступен, фото не отправлено», а снимки из истории уходят пометкой. В ассистенте перед ответом звучит «Отвечает запасная модель» (в потоке — только если сбой до первого слова), в переводе — только метка. Сообщения `LlmException` («нет интернета» и т. п.) ещё и озвучиваются в канал ME — с очками на экран не смотрят.
- У каждого ответа — метка модели (`Answer.tag`, подпись собирает `modelLabel`): в чате и в ленте перевода. Без ключа для выбранной модели кнопки неактивны, вместо ошибки — `MissingKeyNotice`.
- Отказ модели: у Claude `stop_reason: refusal`, у DeepSeek `finish_reason: content_filter` → `Answer.text = null` → «не могу ответить» / «перевод недоступен».
- Имитация сбоев — `DebugFaults` (только debug).

**Потоковые ответы ассистента** (`answer/`, `ChatProvider.stream`). Ассистент получает ответ потоком: у Claude — `createStreaming` (только текстовые дельты, thinking пропускается), у DeepSeek — SSE (`stream_options.include_usage`, `reasoning_content` пропускается; разбор строк — `OpenAiCompatibleFormat.parseStreamLine`). Перевод остался на `complete`.
- Ответ двухуровневый: суть в 1–2 предложениях, строка-маркер `⟦more⟧` (`SpokenAnswer.MARKER`, его же называет системный промпт), подробности. `SpokenAnswer` отдаёт в озвучку только предложения сути (маркер может прийти частями; без маркера — не больше 3 предложений), подробности — в чат под «Подробнее»; маркер не показывается и в память не попадает (в памяти — суть + подробности).
- `SentenceSplitter` режет поток на предложения: не режет на числах (`3.5`, `$4.99`), сокращениях из `res/raw/abbreviations.txt` (`*` в конце строки — сокращение может завершать предложение: «и т. д.»), инициалах и строчной букве после знака. Предложения идут в `Channel`, отдельная корутина проговаривает их подряд, пока модель пишет дальше.
- Запасная модель — только если сбой до первого слова (`LlmService.stream`, событие `onFallback` → «Отвечает запасная модель» первой фразой). Обрыв посреди ответа: сказанное остаётся, звучит ошибка, без повтора. Сторожевой таймер: 20 с без единого события потока (`onEvent`) — ошибка сети, а не ожидание таймаута чтения.
- **Перебить** — кнопка микрофона во время «думаю/говорю» (`Phase.interruptible`) или кнопка гарнитуры: запрос и речь останавливаются, сразу слушается новый вопрос. Касание остального экрана ответ не прерывает. Кнопка гарнитуры — `HeadsetButtons`: медиасессия создаётся на время ответа и уничтожается после (иначе она перехватывала бы кнопки у музыки); пока ответ идёт, в процессе крутится беззвучный `AudioTrack` — Android отдаёт кнопки приложению, которое само играет звук, а TTS играет в процессе движка синтеза. Проверка без гарнитуры: `adb shell input keyevent KEYCODE_MEDIA_PLAY_PAUSE` (или `KEYCODE_HEADSETHOOK`).
- **Голосовое «стоп»** (настройка «Гарнитура», по умолчанию выключено, только с гарнитурой с микрофоном): `AudioRouter.holdMic()` держит SCO на весь ответ (включается параллельно с запросом к модели), распознаватель по кругу ждёт `R.array.stop_commands`; ответ при этом звучит в качестве звонка — у классического Bluetooth микрофон и A2DP одновременно не работают. «Стоп» только останавливает, без нового вопроса.
- Пока звучит речь (ассистент и перевод), музыка других приложений приглушается: `AudioFocus` — `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, захваты считаются; ответ ассистента держит фокус целиком (`AudioOutput.holdFocus`), чтобы музыка не всплывала между предложениями.
- Замер: лог `Glasses` `Assistant: end_of_speech→sound=`; в строке `LLM` потока — `first_text=` (время до первого слова модели). Замер на 5 вопросах × 2 (медиана, мс): Sonnet 3551 (до стриминга) → 3479 (стриминг) → 2830 (стриминг без размышлений); DeepSeek Flash 2586 → 2515 → 2132. Основное время — до первого слова модели (`first_text`: Sonnet ≈ 2,0 с, DeepSeek ≈ 1,3 с), ещё ≈ 0,8 с — дописать первое предложение и запустить TTS.

**Память ассистента** — `Conversation` (чистый Kotlin, покрыт тестами): окно обрезается пачкой (10 обменов → последние 5), чтобы реже сбивать кэш; картинкой отправляется только последний снимок, старые — пометкой «[фото]». **Ответы Claude хранятся только текстом, без thinking-блоков**: у Sonnet 5.5 thinking-блоки привязаны к неизменной истории, и после обрезки окна или замены фото их повторная отправка дала бы 400 на новых аккаунтах. Кэш срабатывает от 512 токенов — короткие текстовые разговоры не кэшируются, это нормально. Сброс: кнопка, голосом «новый разговор» / «забудь всё» (`Conversation.isResetCommand`), автосброс через 5 минут тишины.

**Инструменты ассистента** (`llm/Tools.kt`, `claude/AssistantTools.kt`). Цикл инструментов — внутри провайдера, в `stream`: у Claude `tool_use` → результаты → следующий раунд (ответ модели возвращается целиком через `MessageAccumulator` + `addMessage(Message)` — с thinking-блоками и результатами поиска, так требует API; `pause_turn` — продолжить), у DeepSeek `finish_reason: tool_calls` (куски вызова собирает `ToolCallAssembler`, `reasoning_content` возвращается). Не больше `MAX_TOOL_ROUNDS` раундов; текст всех раундов идёт одним потоком, `Usage` суммируется. Пока выполняется инструмент, сторожевой таймер потока «подкармливается» (`onEvent`).
- **Веб-поиск** — только Claude (`ModelSpec.webSearch`): серверный `web_search_20250305` (базовый — быстрее, чем `_20260209` с фильтрацией через code execution), `max_uses: 3`, `user_location` — страна (сеть или регион телефона) и часовой пояс. Промпт: искать только ради свежих данных, ничего не писать до поиска, ссылки не читать. Ссылки — из цитат `web_search_result_location`, без цитат — первые 3 результата; под ответом кнопками (`openLink`, только http/https). Цена — $10 за 1000 поисков (`ModelPrices.WEB_SEARCH_USD`, `usage.server_tool_use.web_search_requests`, неудачные не оплачиваются) плюс токены результатов во входных; в логе `web=`, в журнале `web_searches`. Модель без поиска (DeepSeek — выбранная или запасная): поиск убирается, в промпт — `NO_WEB_SEARCH_NOTE` («честно скажи, что проверить не можешь»), у ответа метка «· без поиска», в настройках у моделей ассистента — «без поиска в интернете».
- **Заметки «Запомни»** (`notes/`): `NoteStore` — `files/notes/notes.json` + `<id>.jpg`, только на телефоне. Инструменты `save_note` / `find_notes` / `delete_notes`; модель получает только текст, время и флаги `has_photo`/`has_location` — без координат и фото. Поиск — `NoteSearch` (основы слов без двух последних букв, тесты). Фраза начинается с «запомни» (`R.array.remember_triggers`) — снимок и координаты готовятся параллельно с запросом; снимок — из выбранного источника (галерея — нет), почти чёрный кадр с камеры телефона не прикрепляется (`ImagePrep.isDark`). Координаты — `DeviceLocation` (разрешение спрашивается при первой заметке). Повтор той же заметки за 10 минут не дублируется (модель пересохраняла просьбу из прошлого хода — история у нас только текстом). Карточки в чате: снимок, время, «Проложить маршрут» (`geo:`). Экран «Заметки» — значок в шапке ассистента, поверх вкладки, закрывается «Назад».
- **Защита от чужих команд** (`ToolPlan`): текст на снимках и страницы из поиска могут содержать инструкции, поэтому `delete_notes` даётся, только если в МОЕЙ фразе есть слово из `R.array.delete_note_triggers` («удали», «забудь», «delete», «forget»…), и тогда без веб-поиска; в «Переведи, что вижу» — ни удаления, ни поиска, ни заметок. «Забудь всё» целиком — по-прежнему сброс разговора.
- **«Переведи, что вижу»** (`AssistantMode.TRANSLATE_VIEW`): кнопка справа от микрофона или фраза из `R.array.translate_view_commands`. Снимок → весь текст на язык приложения; вслух — что это и главное, полностью — в чате (развёрнуто сразу, есть «на весь экран»). Инструмент `convert_prices` — курс ЦБ РФ в «Мою валюту» (настройка, по умолчанию RUB). `rates/CbrRates`: cbr.ru (`XML_daily.asp`, windows-1251), при недоступности — зеркало cbr-xml-daily.ru (`daily_utf8.xml`, тот же формат); кеш `files/cbr_rates.json` на день, обновляется при появлении сети (`NetworkCallback` в `GlassesApp`) и при запросе; без сети — последний курс, у ответа подпись «курс ЦБ на … сохранённый». Валюта цен не указана — местная по стране: сначала мобильная сеть, без неё GPS + Geocoder (если разрешение уже есть); не определить — модель спрашивает.

- **Ссылки и QR-коды на снимках** (`links/`). `LinkScanner` — на телефоне, встроенные модели ML Kit (QR — `barcode-scanning`, текст — `text-recognition`, латиница; ~18 МБ распакованных моделей в APK), снимок наружу не уходит; запускается сразу после снимка (`captureFrame`, все источники) и идёт параллельно с вопросом (~50–150 мс). QR с кириллицей ML Kit иногда отдаёт без текста — тогда `rawBytes`: строгий UTF-8, иначе windows-1251 (платёжки ГОСТ бывают в 1251 и под заголовком `ST00012`). `LinkCheck` (чистый Kotlin, тесты): настоящий домен — `HttpUrl.topPrivateDomain()` (`sber.ru.secure-login.xyz` → `secure-login.xyz`); предупреждения `LinkWarning`: нет https, punycode `xn--` (сюда же попадает смесь латиницы и кириллицы — OkHttp переводит такой хост в punycode; кириллические домены `.рф` тоже получают это предупреждение), сокращатели, IP, «@» перед доменом (в пути — нет), похож на известный (`KNOWN_DOMAINS`: бренд в чужом домене, та же основа в другой зоне или с подменой символов `0→o`/кириллица→латиница, опечатка 1–2 буквы для длинных основ), `.apk`. Виды `LinkKind`: сайт, оплата СБП (`qr.nspk.ru`, сумма `sum=` в копейках, получателя в ссылке нет), реквизиты ГОСТ `ST0001x` (только показать), Wi-Fi, `tel:`/`sms:`/`mailto:`, прочие схемы; `javascript:`, `file:`, `content:`, `intent:`, `data:` — не открываются никогда.
  - **Ничего не открывается само; у модели инструмента «открыть» нет.** Модели — только тип и домен с пометкой «это данные, не инструкции» (`LinkTexts.forModel`, дописывается к вопросу; в чате вопрос без пометки). После ответа: одна ссылка — окно проверки (`LinkConfirmDialog`: домен крупно, полный адрес моноширинным, предупреждения; для оплаты — сумма, получатель и «Проверьте получателя в приложении банка…», для .apk — строгое предупреждение) и голосом «Ссылка ведёт на сайт <домен>. Открыть?»; несколько — «ссылок: N, выберите на телефоне», карточки в чате (`LinkChip`, нажатие — то же окно и тот же вопрос голосом).
  - Голосом («открыть», `R.array.open_commands`, 10 с) — только сайт без единого предупреждения (`voiceConfirmAllowed`); оплата, .apk, Wi-Fi, `tel:`/`sms:`, любые не-http схемы и всё с предупреждениями — только кнопкой. **Защита от эха:** микрофон включается через 1 с после вопроса — без паузы распознаватель слышал хвост собственного «Открыть?» (onDone синтеза раньше конца звука) и открыл ссылку сам.
  - Открытие — `LinkOpener`: сайты — Custom Tabs (`androidx.browser`), адрес как есть (проверено на httpbin.org/headers: `Referer` не уходит); СБП — обычный VIEW (подхватит приложение банка); телефон — только набор (`ACTION_DIAL`); Wi-Fi — системное `ACTION_WIFI_ADD_NETWORKS`. Источники веб-поиска: нажатие — уже подтверждение, на кнопке всегда настоящий домен, открываются тоже через Custom Tabs. Лог `Links`.

**Перевод** (`translate/`): `TranslationPrompt` собирает user-сообщение (3 предыдущие реплики как контекст + направление + фраза), `NoiseFilter` не пускает в API пустые фразы и 1–2 междометия. В `TranslationViewModel.turn` микрофон снова включается только после окончания озвучки + 400 мс (защита от эха). Голос TTS для языка проверяется заранее (`VoiceStatus`); если не скачан — подсказка и кнопка, открывающая установку голосов текущего движка (`Speaker.enginePackage`).

**Источник снимков** (`camera/`) — `ImageSource`, выбирается чипом «Снимки ▾» на вкладке «Камера» (шторка снизу; `ImageSourceSettings`, по умолчанию «Очки»):
- «Очки» — DAT SDK. Не подключены — «Что я вижу» не блокируется, а говорит «Очки не подключены…» и подсказывает камеру телефона; автоматически не переключает (телефон может лежать в кармане).
- «Камера телефона» — CameraX (`PhoneCamera`), задняя камера: большой видоискатель «Камеры», `ImageCapture` по затвору. Камера привязана к жизненному циклу видоискателя — включена только пока он на экране; «Что я вижу» из «Ассистента» (видоискателя нет) — `captureWithoutPreview(Activity)`: камера включается на один снимок; перед ним — фокус и экспозиция по центру (`startFocusAndMetering`, ждём до 1,5 с, лог `Image` `one shot focus=… after=…ms`; на S25 ≈ 0,9 с, +0,5 с к ответу) — без этого снимок уходил до наведения фокуса и был размыт. Разрешение `CAMERA` запрашивается при выборе источника; если его отозвали в настройках Android — вместо чёрного видоискателя «Нет доступа к камере» и «Разрешить» (`MainActivity.cameraGranted` перепроверяется в `onResume`).
- Галерея — не источник (`ImageSource.GALLERY`, `pickable = false`: метка снимков и запасной вариант восстановления), а первая плитка ленты: системный `PickVisualMedia` — приложение получает только выбранный снимок, разрешений нет; снимок становится выбранным.
- «Симулятор очков» — только в debug-сборке; он же включает MockDeviceKit (`GlassesManager.setMockMode`, в release всегда выключен; заряд симулятора — 76 %).
- Все снимки проходят `ImagePrep`: поворот (с камеры — `rotationDegrees`, из галереи — EXIF через `ImageDecoder`), длинная сторона ≤ 1024 px и перекодирование `Bitmap.compress` — EXIF (в т. ч. GPS) не уходит. Debug-лог `Image`: `exif_в_исходнике=… exif_в_отправляемом=false`. У снимка в чате — метка источника.
- **Лента снимков** — `ShotStore`: каждый снимок (из «Ассистента» и «Камеры») — в `files/shots/<время>.<источник>.jpg`, последние 30, старые удаляются сами; только на телефоне. Нажатие на плитку — следующий вопрос в «Камере» о ней (`UiState.selectedShot`, «К живому кадру» — назад), долгое — «Сохранить в галерею» (MediaStore, `Pictures/Glasses`, без разрешений) или «Удалить».

**Вкладка «Камера»** (`ui/CameraScreen.kt`, та же `MainViewModel`, что у «Ассистента», — разговор общий):
- Строка чипов 44 dp: «Снимки ▾», «Микрофон ▾» (шторки снизу), справа «Подключить очки» или «● Очки · 76 %» (`GlassesManager.battery` — `Device.batteryLevel` из `Wearables.devicesMetadata`).
- Микрофон (`speech/MicSettings`, `MicChoice`): «Авто» — гарнитура, если подключена, иначе телефон; «Гарнитура»; «Телефон» — `AudioRouter.micChoice` не берёт гарнитуру для моего голоса; «Очки» — неактивно («скоро», DAT Speech — следующий этап). Собеседника в «Переводе» всегда слушает телефон.
- Видоискатель: камера телефона, последний кадр с очков (последний снимок ленты из очков) или выбранный снимок. Затвор «Что я вижу» (глаз): нажатие — описать (`cameraDescribe`), удержание — снимок и свой вопрос голосом (`cameraAsk`); слева «Переведи» (`TRANSLATE_VIEW`), справа «Запомни».
- Ответ — шторкой поверх снимка (`UiState.cameraSheetId`, ход начат в «Камере» — `cameraTurn`): суть, «Подробнее», чипы ссылок (проверка — как везде, `AssistantOverlays`), микрофон «Спросить ещё» (вопрос о том же снимке — он остался в разговоре картинкой). В историю «Ассистента» обмен попадает как обычно.
- «Запомни» (`cameraRemember`, без модели): снимок → «Что запомнить?» → пауза 1 с от эха → голос — текст заметки; молчание — заметка без текста (снимок, время, место; в списке — «Снимок без текста»). Почти чёрный кадр с телефона не прикрепляется.

**Вкладка «Ассистент»**: сверху индикатор очков (`GlassesIndicator`: «● Очки · 76 %» / серое «Не подключены», нажатие — «Камера»; скрыт, пока очки ни разу не подключались (`GlassesManager.everConnected`) и источник — телефон), «Заметки», «Новый разговор». Пустой чат — подсказка в 3 строки. Внизу: подпись состояния, «Написать текстом» (шторка с полем; ответ без голоса, `ChatItem.silent` → «Озвучить»), капля микрофона, глаз «Что я вижу» (снимок и описание, без вопроса голосом). Источники поиска — свёрнутым чипом «Источники (N)». Метка модели под ответом — только если ответила не основная модель (запасная, DeepSeek, «для фото», «без поиска») или у роли «Разработчик». Голосовые команды («Что я вижу», «Переведи, что вижу», «Запомни…», «Новый разговор», «стоп») понимают микрофоны «Ассистента» и «Камеры»; в «Переводе» микрофон слушает собеседника — команды там не распознаются.

**Оформление** (`ui/`):
- Тема — `GlassesTheme(dark)`: dynamic color на Android 12+, светлая/тёмная по системе; запасная палитра M3 на бирюзовом `#00696B` (цвет иконки). Заставка — `core-splashscreen` (`Theme.Glasses.Starting` → `postSplashScreenTheme`), `installSplashScreen()` до `super.onCreate`.
- Иконка приложения — адаптивная (`mipmap-anydpi-v26/ic_launcher.xml`): облачко речи с очками + монохромный слой для тематических иконок; рисунок внутри безопасной зоны (круг R=33 из 108).
- Иконки — Material Symbols Outlined как векторные XML (`res/drawable/ic_sym_*.xml`, скачаны из `google/material-design-icons`, атрибут `android:tint` удалён — цвет задаёт `Icon`). `material-icons-extended` не используем. Невыбранные варианты лежат в `src/debug/res` — только для витрины.
- Витрина вариантов иконок — только debug: `adb shell am start -n ru.vasev.glasses/.debug.ShowcaseActivity`; выбор пишется в лог `Showcase` и в `shared_prefs/showcase.xml`.
- `MicButton` — стеклянная капля (см. «Стекло»): покой / «слушаю» (свечение по громкости — `SpeechSource.listen(onLevel)` из RMS распознавателя) / «думаю» / «говорю»; во время ответа нажатие перебивает, пока снимаем или слушаем — «стоп». `Haptics` — щелчок в начале и двойной в конце прослушивания (только ассистент).
- Чат: пузыри, метки модели и источника снимка — под пузырём; снимок и перевод открываются на весь экран (`FullscreenPhoto`, `FullscreenText`).
- Доступность: у иконок без текста — `contentDescription`, у иконок рядом с текстом — `null`; строка «подпись + Switch» — один `toggleable(role = Switch)`. Проверка: `uiautomator dump` — у каждого кликабельного узла (с потомками) есть подпись и он ≥ 48 dp (на S25 это 135 px).
- Скриншоты в светлой теме: `adb shell cmd uimode night no` — после проверки вернуть исходное значение (`cmd uimode night` показывает текущее).

**Стекло** (`ui/glass/`, «лёгкое стекло», выбрано на витрине). Haze 2.0.1 (`haze`, `haze-blur`, `haze-glass`, `haze-blur-materials`).
- `GlassRoot` — фон и окружение стекла: `GlassBackground` (градиент из цветов обоев, 3 пятна по фигурам Лиссажу, рисуется в фазе отрисовки) — источник размытия `GlassLayer.BACKGROUND`; цвет текста по умолчанию — onSurface (непрозрачного `Surface` больше нет — без этого текст был бы чёрным в тёмной теме). Фон стоит на вкладке «Перевод», в энергосбережении (подписка на `ACTION_POWER_SAVE_MODE_CHANGED`) и при «Убрать анимацию» (`ValueAnimator.areAnimatorsEnabled`).
- `Modifier.glass(shape, tint, text, blur)`: подложка + блик по краю + тонкая обводка + тень **только снаружи** (`outerShadow`: размытый контур с вырезанной формой, кэшируется в ALPHA_8-картинку на размер — системная тень и `dropShadow` просвечивают сквозь стекло, а `BlurMaskFilter` в каждом кадре нагружал видеокарту). `blur = true` — только у панелей поверх прокручиваемого содержимого (вкладки, кнопки внизу, капля): размывают `GlassLayer.CONTENT` (`glassContentSource()` на списке) и фон. Карточки и пузыри на фоне без размытия — под ними гладкий градиент, а каждый размытый элемент перерисовывается при прокрутке.
- **Контраст ≥ 4.5:1 — рассчитывается** (`Contrast`, чистый Kotlin под тестами): плотность подложки — наименьшая, при которой текст держит 4.5:1 против всего, что может оказаться позади (цвета фона; под панелями ещё пузыри и размытый текст), но не ниже 0.14 (цветное стекло — 0.45, иначе на тёмном фоне собеседник и я не различаются). Акцент (`glassAccent`) и второстепенный текст на фоне (`glassBackgroundText`) подтемняются к onSurface ровно до 4.5:1 — у палитры обоев Samsung `primary` на светлом стекле давал 3.7:1. Подпись выбранной вкладки — всегда onSurface (под панелью проезжает содержимое любой яркости), выбор — пилюлей, жирным и акцентной иконкой. Проверка по пикселям: скрипт сравнивает 3-й и 97-й перцентили яркости в рамке каждого текста из `uiautomator dump`.
- «Меньше прозрачности» (простые настройки, `ProfileSettings.lessTransparency`) — подложка +0.3, размытие ×1.5; включается и само при системных «Текст высокой контрастности» / повышенном контрасте (Android 14+). Android 11 и ниже — без размытия, подложка плотнее (+0.25).
- Компоненты: `GlassButton` (пилюля, виды PRIMARY / NORMAL / TONAL_TERTIARY / ERROR), `GlassIconButton`, `GlassCard`; `MicButton` — стеклянная капля: свечение внутри по состоянию (слушаю — по громкости, думаю — бегущий блик, говорю — дыхание). Выпадающие меню — отдельные окна, их не размыть: оставлены непрозрачными M3. Полноэкранный перевод — непрозрачный (читают издалека и на солнце). Неактивная кнопка — бледнее только текст и иконка (`DISABLED_ALPHA`), не `Modifier.alpha`: смена alpha слоя «неактивна → активна» оставляла кнопку без подложки и обводки.
- Витрина вариантов (лёгкое / матовое / жидкое на Backdrop / гибрид) — только debug: `adb shell am start -n ru.vasev.glasses/.debug.GlassShowcaseActivity`; Backdrop (`io.github.kyant0:backdrop`) подключён только к debug.
- Плавность (S25 Ultra, 120 Гц — проверено по `FrameInterval` 8,3 мс в `dumpsys gfxinfo framestats`): прокрутка чата — 0 кадров из 120 не уложились в `FrameDeadline`, «тормозящих» по всему замеру 0,07 %; кадр занимает 12–14 мс, но благодаря конвейеру отрисовки укладывается в свой срок. Прокрутка настроек и перевод — 0,21 % и 0,71 % «тормозящих» (до стекла 0,35–2,31 %).

**Язык** (`i18n/`). Все строки — в ресурсах: английский по умолчанию (`values/`), русский (`values-ru/`); в Kotlin-коде нет кириллицы, кроме комментариев (тесты — по-русски). Междометия для `NoiseFilter` — данные в `res/raw/noise_fillers.txt`. Язык приложения (Системный / Русский / English) — per-app language: `AppCompatDelegate.setApplicationLocales` + `res/xml/locales_config.xml`, на Android 10–12 сохраняется через `AppLocalesMetadataHolderService`; поэтому `MainActivity` — `AppCompatActivity`, а обе темы (`Theme.Glasses` и `postSplashScreenTheme`) — наследники AppCompat. Язык приложения = язык общения с ассистентом: распознавание, голос, ответ модели, голосовые команды (`R.array.reset_commands`) и «мой язык» в переводе (`PartnerLanguage.forApp`; в списке собеседника нет моего языка, русский есть). Код вне экрана берёт строки через `L.s(...)` (контекст с языком приложения), язык — из `LanguageSettings.current` на каждый вопрос/фразу, поэтому смена языка действует сразу. На Android 13+ `MainActivity` не пересоздаётся (`configChanges="locale|layoutDirection"`): Compose перерисовывает строки на месте, `onConfigurationChanged` обновляет язык общения и подсветку выбора в настройках — раньше пересоздание давало чёрный/белый кадр (моргание). На Android 10–12 AppCompat пересоздаёт Activity сам: ViewModel и история остаются, вкладка — в `onSaveInstanceState`; до первого кадра фон окна — цвет градиента (`glassesColorScheme(...).surface`), а анимация фона идёт от часов процесса (`BackgroundClock`), без скачка. Промпты — на английском с названием языка (`englishName`); качество перевода на русский проверено против прежних русских промптов — без разницы. Логи — на английском. Проверка без кнопок: `adb shell cmd locale set-app-locales ru.vasev.glasses --locales en` (пусто — системный).

**Навигация** (`nav/`, `places/`, `ui/NavigationScreen.kt`; лог `Navigation`, `Geocoder`). Все 5 этапов: места и цель, компас, такси, советы по транспорту, голосовые команды.
- Устройство: общее состояние — `NavSession` (в `GlassesApp`): что открыто (цель, такси, моё место), где я, подсказка под полем «Куда?», текущее действие (`launchTask` — одно за раз, новое отменяет прежнее; `cancel` при смене вкладки), переходы в карты и такси (`open`/`launch`, одноразово), «Очистить» (`cleared` — экраны сбрасывают своё). Закрыли приложение («Назад») — `closeScreens()`: экраны с начала, компас работает.

Отель, дом, машина — по одному (повторное сохранение заменяет), свои — сколько угодно. «Сохранить здесь» — GPS + фото входа из выбранного источника (очки, если подключены, иначе камера телефона — через видоискатель `NavViewfinder`: затвор, «Без фото», «Назад» отменяет сохранение; голосом «Запомни, это мой отель» — без видоискателя, почти чёрный кадр не прикрепляется) + адрес точки от геокодера.

- «Куда?»: `NavQuery` (тесты) убирает «как добраться до…» и узнаёт мои места («в отель», «домой»); иначе — `AddressGeocoder` (встроенный `Geocoder`: только с сетью, пустой ответ не отличает «не нашёл» от «нет сервиса», результат — догадка; на Android 13+ — слушатель, раньше — блокирующий вызов в IO; сначала ±0,5° вокруг меня, потом везде). Google находит почти любое название, поэтому под результатами всегда «Не то? Найти через ИИ».
- Фото адреса: `AddressOcr` (ML Kit, латиница; русский, тайский, арабский не читает) → геокодер → подтверждение. «Распознать через ИИ» / «Найти через ИИ» — только по кнопке, `AddressAi` через модель ассистента по общим правилам `LlmService` (запасная модель, фото в неё — по настройке). В модель — только название и «город, страна», без координат; координаты — только от геокодера по адресу модели; перед «Адрес верный» — «Проверить на карте». DeepSeek без поиска отвечает из своих знаний, метка «· без поиска».
- Карточка цели: расстояние по прямой, время ≈ ×1,3 / 80 м/мин (дальше 20 км — только «по прямой»); пешком дольше 20 мин — транспорт первым (`Geo`, тесты). Ссылки — `NavigatorLinks` (тесты): Google `google.navigation:q=…&mode=w` и Maps URL `travelmode=transit`; Яндекс `yandexmaps://maps.yandex.ru/?rtext=A~B&rtt=pd|mt` (старт — мои координаты); Organic Maps `om://route?…&type=pedestrian`; `geo:`. Настройка «Навигатор» (`NavigatorSettings`): Авто (Россия по сети — Яндекс, иначе Google) / Яндекс / Google; не установлен — что есть. Без сети и Google — окно с Organic Maps. Пакеты карт — в `<queries>` манифеста. Проверено на S25: Яндекс (транспорт), Google (пешком), `geo:` в выбранном приложении.
- Служебное (точность GPS) — только разработчику; остальным — предупреждение при GPS хуже ±100 м.
- **Компас** (этап 2; лог `Compass`): до 1,5 км по прямой — в карточке цели первым. `CompassController` (на всё приложение, в `GlassesApp`) + `CompassService` (foreground, тип location, уведомление со «Стоп»): работает при смене вкладки и с выключенным экраном. GPS раз в секунду (fused), голос — в канал ME. «Взгляд» — `HeadingSource`: экран включён — вектор поворота телефона (истинный север через `GeomagneticField`; лёжа — верх экрана, стоя — задняя камера), выключен — направление движения по GPS (≥ 0,8 м/с), иначе — стороны света. Правила подсказок — `CompassGuide` (тесты): первая — «по прямой» + время (ждёт датчик до 2 с); смена сектора (8 по 45°, запас 10°) после 3 с и не чаще 8 с; отметки 1000/500/300/200/100/50 м по минимальному расстоянию; «Вы на месте» в 20 м (при плохом GPS — до 35 м), после — всё выключается; за 2 мин прошёл ≥ 60 м, а ближе < 20 м — «откройте навигатор» (баннер); 30 мин без перемещения > 25 м — автостоп. Числа в речи — plurals (`L.q`).
- **Наша речь уступает навигатору** (`NavigatorVoice`, лог `Audio`): чужие воспроизведения с usage `ASSISTANCE_NAVIGATION_GUIDANCE` видны через `AudioPlaybackCallback` (Google Maps — проверено). `PhoneSpeakerOutput.speak`: навигатор говорит — ждём (до 15 с); заговорил посреди нашей фразы — `speaker.stop()` и повтор фразы после него (один раз). Действует на всю озвучку (ассистент, перевод, компас).
- **Такси** (этап 3; лог `Taxi`): «Такси» в карточке цели (пешком дольше 20 мин — сразу после транспорта) и «Адрес таксисту» у моего места → `TaxiScreen` (непрозрачный): адрес на местном языке крупно (`LocaleList` языка — правильные глифы), на языке приложения мелко, Plus Code (`PlusCode`, тесты, по спецификации — floor), фото входа, «Произнести» (TTS на местном языке в канал PARTNER — динамик телефона; нет голоса — подсказка), кнопки установленных приложений такси (`TaxiApp`, пакеты в `<queries>`). С пунктом назначения — только документированные ссылки: Яндекс Go `https://3.redirect.appmetrica.yandex.com/route?end-lat=…&end-lon=…` (проверено), Uber `uber://?action=setPickup&pickup=my_location&dropoff[…]`; остальные просто запускаются.
- Язык адреса — настройка (Авто по стране цели — `CountryLanguage`, тесты — или вручную). `TaxiAddresses` (на всё приложение): геокодер на местном языке (принимаем, только если письмо совпало — `scriptMatches`, иначе он молча отдаёт латиницу), название места и запасной путь — модель роли «Перевод» (ответ `NAME:`/`ADDRESS:`). Адрес «Дом» — модели только по кнопке «Перевести через ИИ». Переводы моих мест хранятся в `places.json` (`local_*`) и считаются заранее: после сохранения места, при появлении сети, при смене языка. Язык совпал с языком приложения — перевода нет. Проверено: Ват Арун — тайский адрес геокодером + название Haiku, сохранён, в авиарежиме показан.
- **Советы по транспорту** (этап 4; лог `Transit`): под «Транспортом» в карточке цели; пешком дольше 20 мин — загружаются сами (если есть сеть и ключ), иначе кнопка. `TransitTips`: модель ассистента с веб-поиском (2 поиска, `max_tokens` 2048 — размышления Sonnet между поисками входят в лимит, при 500 ответ обрывался), в модель — только «район, город, страна» начала и цели (геокодер на английском, `FoundAddress.district`), без адресов и названий; ответ — до 4 строк «• …» (`TransitTips.bullets`, тесты: текст раундов поиска склеен без переносов). Кэш на день в памяти; авто-кэш промпта выключен (разовый запрос — запись в кэш ~18 тыс. токенов зря), как и у `AddressAi`. DeepSeek: своя приписка `noWebSearchNote` (общие советы без чисел), метка «без проверки в интернете». Источники — `SourceLinks`, «в модель: …» — только разработчику.
- **Веб-поиск Claude и страна:** `user_location.country = TH` даёт 400 «Country code TH is not supported» — `AnthropicProvider` повторяет запрос без страны и запоминает её до перезапуска (касается и ассистента за границей). Текст 400 от Anthropic пишется в лог `LLM`.
- **Голосовые команды** (этап 5): `NavCommands.parse` (тесты) в ходе ассистента до модели — микрофоны «Ассистента» и «Камеры» (в «Переводе» микрофон слушает собеседника). «веди в …» / «как добраться до …» (моё место или геокодер: голосом список не выбрать — ближайший результат, название — `FoundAddress.name`, дальше 300 км — «уточните на экране»), «как вернуться» (отель, иначе дом), «назад к началу маршрута» (где я был, когда выбрал цель; `NavigatorSettings.routeStart`, переживает выгрузку процесса), «покажи адрес таксисту», «сколько осталось», «где машина», «запомни, это мой отель / здесь машина / мой дом» (место здесь вместо заметки). Цель ближе 1,5 км — сразу «Компас», дальше — расстояние голосом и карточка. Ответ — голосом в канал ME. Вкладка «Навигация» открывается после хода (`navCommandDone`), без остановки ассистента. Фразы — массивы `nav_cmd_*`, `nav_remember_*`. Автозагрузка советов по транспорту — только до 50 км.
- **Haze и пустой чат:** список чата — источник размытия; если его убрать (пустой чат → подсказка вместо `LazyColumn`), Haze 2.0.1 падает «LayoutCoordinate operations are only valid when isAttached is true». Поэтому `LazyColumn` есть всегда, подсказка — его элемент. Стек падений — `adb shell dumpsys dropbox --print data_app_crash`.
- Проверка компаса за столом (debug): `--es fake_location 'lat,lng'` (каждый интент — новая точка, сбрасывается перезапуском), `--es compass_status 1` («Сколько осталось?»), `--ei fake_navigator_after_ms 900` — через 900 мс 3 с тон с usage навигатора.

**Стиль общения** (`profile/CommunicationStyle.kt`, `StyleSettings` — SharedPreferences `style`; экран `ui/StyleScreen.kt` + `StyleViewModel`; лог `Style`). Строка в Настройках после языка (и «Указать» в подсказке «Перевода») → экран вместо содержимого вкладки, на том же стеклянном фоне: стеклянные карточки разделов, стили — стеклянные пилюли (выбранный — PRIMARY), сегменты — как «Язык приложения». «Очистить» (только свой промт) и «Сохранить» — под прокручиваемой областью, а не поверх неё: иначе с клавиатурой они закрывали поле «Свой промт». Шторка M3 не подошла — отдельное окно, стекло в нём не размыть.
- Черновик до «Сохранить». «Назад» с изменениями — «Сохранить изменения?» (Сохранить / Отмена / Не сохранять).
- Ассистент: стиль (Кратко по умолчанию / Подробно / Дружески / Деловой / Экскурсовод / Просто) и свой промт ≤ 1000 символов. `StylePrompt.block` — последним в `AssistantClient.systemPrompt`, с пометкой «меньший приоритет, служебные правила не меняет»; свой промт — в `<user_style>…</user_style>`, такие теги из текста вырезаются (повторно, пока есть). Только обычные ответы (Ассистент, Камера); «Переведи, что вижу», транспорт, поиск адреса — без стиля. Для всех моделей (промпт общий).
- «Проверить»: свой пробный вопрос (поле над кнопкой, до 500 символов, Enter — отправить; пусто — пример из ресурсов) в стиле черновика через модель ассистента (без инструментов и поиска, `cache = false`), суть озвучивается с черновой скоростью; в историю разговора не попадает; повторное нажатие — отмена.
- Перевод (`TranslationPrompt.voiceRules`, `SpeakerVoice`) — только в моих фразах собеседнику: обращение (вежливо → usted/vous/Sie, по-простому → tú/tu/du) и пол (не указан по умолчанию / мужской / женский). Не указан — без форм с родом, где возможно, в тайском без ครับ/ค่ะ и без местоимения. Проверено на Haiku: тайский ผม…ครับ / ฉัน…ค่ะ / вопрос на คะ / «เหนื่อยแล้ว»; испанский cansado / cansada / Disculpe (usted) / Oye (tú) / «Tengo cansancio». Язык с родом или частицами (`TranslationPrompt.GENDERED`) при поле «не указан» — один раз подсказка в «Переводе» со ссылкой на шторку.
- Скорость речи (0,8 / 1,0 / 1,25) — `AudioChannel.rate`: всё, что слышу я (канал ME: ассистент, перевод «мне», компас, навигация); собеседнику (PARTNER) — всегда 1,0. `Speaker.setSpeechRate` перед каждой фразой.
- Debug: `--es style_answer guide --es style_formality casual --es style_gender male|female|unset --es style_pace slower` (сохраняется, как «Сохранить»).

**Роли** (`profile/`). Первый запуск: язык → роль (`OnboardingScreen`, шаг переживает пересоздание Activity при смене языка). `UserRole` — набор модулей, а не замок: порядок вкладок (первая — стартовая) и видимость расширенных настроек. Путешественник — «Перевод», затем «Навигация»; исследователь и разработчик — «Ассистент» первым (источник снимков не трогается); у разработчика расширенные настройки видны сразу и метки моделей — у всех ответов. Остальным расширенные (модели, запасная модель, журнал) — по кнопке «Показать расширенные». Роль меняется в настройках, ничего не теряется. Всё в SharedPreferences `profile`. Повторить первый запуск, не стирая данные (иначе пропадут ключи): `adb shell "am start -n ru.vasev.glasses/.MainActivity --ez reset_onboarding true"`.

**Журнал запросов** (`llm/RequestJournal`): запись на каждую попытку, как строка лога `LLM`; JSONL `files/requests.jsonl`, последние 1000. По умолчанию только метаданные, тексты вопроса и ответа — отдельным переключателем (выключен). Стоимость — оценка по `ModelPrices` (Claude — прайс Anthropic; DeepSeek — пиковые цены, вне пика (будни 01–04 и 06–10 UTC — пик) ×0,5 — скидка оценочная). Для ответов ассистента запись дописывается в конце хода: `first_sound_ms` (конец фразы → первый звук) и `interrupted` (перебит; счёт токенов тогда неполный — у Claude выход приходит только в конце потока). Экспорт — копия в `cache/export` через FileProvider (`${applicationId}.files`) и «Поделиться».

**Очки** (`glasses/`): `GlassesManager.captureJpeg` на каждый снимок открывает короткую DAT-сессию: `createSession` → ждать `STARTED` → `addCamera` → `stream.start()` → ждать `STREAMING` (критическая ошибка стрима ловится сразу) → `stream.capturePhoto()` → стоп. Стабильный `stream.capturePhoto()` выбран намеренно: отдельная съёмка `camera.photo` экспериментальная. `MockGlassesController` поднимает MockDeviceKit: **без `setCameraFeed` симулятор не запускает стрим**, поэтому `MockVideoEncoder` при первом включении кодирует `res/raw/mock_view.jpg` в 2-секундное HEVC-видео (ffmpeg не нужен) и кэширует его.

Настоящие очки (Ray-Ban Meta Gen 2, Meta AI 295, проверено 2026-10-27): регистрация и разрешение камеры через Meta AI работают. `capturePhoto` отдаёт HEIC 1440×1080 **без EXIF-ориентации, боком** (матрица в дужке повёрнута) — `toJpeg` поворачивает альбомный кадр с настоящих очков на 90° по часовой (симулятор — нет); лог `Image` `glasses frame HEIC 1440x1080 rotated=90`.

Ошибки DAT → текст — `DatErrors` (тесты): ошибки сессии (`session.errors`, подписка до `start()`; прерывают ожидание сразу) и регистрации (`Wearables.registrationErrorStream` → `GlassesManager.notice`, карточка под «Подключить очки» в «Камере»). Не сводить в одно «несовместимо»: `DAT_APP_ON_THE_GLASSES_UPDATE_REQUIRED` — обновить DAT в Meta AI, `INSUFFICIENT_SDK_VERSION` — нужна новая сборка, `DWA_OUT_OF_STU_RANGE` — не блокирует (подсказка раз за запуск), `SESSION_ALREADY_EXISTS` — «занято другим приложением» (отдельного кода нет). Исходный код — в лог `Glasses`: `DAT error=… stage=create|session|camera|stream|capture|registration`. «Подключить очки» при уже пройденной регистрации не регистрирует повторно, а подсказывает проверить очки в Meta AI.

Подводные камни DAT: `DatResult.fold` не inline — `return` из лямбды нельзя, используйте `getOrNull()` / `errorOrNull()`. Лог `Wearables SDK already initialized` безвреден (MockDeviceKit инициализирует SDK повторно).

2. **Камера.** Снимок с реальных очков работает (HEIC, поворот — см. «Очки»); осталось замерить время «нажатие → кадр». Если открытие сессии на каждый снимок окажется долгим — держать сессию открытой, пока активна вкладка.
3. **Микрофон очков.** Проверено 2026-10-27: очки — обычная Bluetooth-гарнитура (HFP + A2DP), режим гарнитуры работает с ними без изменений (русский распознаётся Google через SCO, ответ звучит в очках, собеседнику — динамик телефона). **DAT Speech для нас не годится:** язык не задаётся (берётся язык очков, `locale` в пробе так и не пришёл), русская речь даёт пустые результаты, английская распознаётся («Hi, it's me.», conf 0.95), но от последнего частичного до окончательного ≈ 1,9 с; без речи каждые ~5,7 с приходит пустой FINAL. Нужно разрешение `Permission.MICROPHONE` через Meta AI. Проба — debug-only `debug.SpeechProbeActivity` (`adb shell am start -n ru.vasev.glasses/.debug.SpeechProbeActivity --ez autostart true`, лог `SpeechProbe`; `mwdat-speech` — только `debugImplementation`). 4. **Звук в очки** — уже работает через режим гарнитуры (см. п. 3). Исходный план: **новая реализация `AudioOutput`.** Канал `ME` → очки (Bluetooth), канал `PARTNER` должен принудительно идти в динамик телефона — иначе при подключённых очках TTS по умолчанию уйдёт в них. Вероятный путь: синтез в файл/буфер и воспроизведение через `AudioTrack` с `setPreferredDevice` (`TYPE_BUILTIN_SPEAKER` для собеседника, Bluetooth-устройство очков для меня). Защита от эха (`onDone` + пауза) сохраняется.
5. **«Hey Meta, start …».** Voice Invocations — в `mwdat-core`, сессия не нужна. В `MainActivity` проверять `isVoiceInvocationsIntent(intent)` в `onCreate` и `onNewIntent` (не разбирать extras вручную).
